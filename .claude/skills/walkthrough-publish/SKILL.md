argument-hint: "<review_id> <pr号>"
disable-model-invocation: true
allowed-tools: Bash(python3 .claude/skills/walkthrough/scripts/validate_ledger.py *) Bash(cat *)
---

发布走读 `$0` 到 PR `$1`。

1. 读 `.walkthrough/$0/ledger.json` 与 `report.md`。先跑 `python3 .claude/skills/walkthrough/scripts/validate_ledger.py .walkthrough/$0/ledger.json`，失败则停止。
2. 用 GitHub MCP 工具确认 PR `$1` 的 head 与 ledger.scope.head 一致；不一致则告知用户并停止，不发陈旧结论。
3. 用 `pull_request_review_write`（method: create）建 pending review；对每条 `ruling.status == accepted` 的 claim，用 `add_comment_to_pending_review` 在 `file:line` 加行内评论，格式：

   ```
   **[<final_severity 大写>] <title>**
   失败场景：<failure_scenario>
   辩护意见：<defense.evidence 一句话>
   验证：<verification.status>，<method>
   建议：<一句祈使句>
   ```
   最后附 `---` 和 `_Generated by [Claude Code](https://claude.ai/code)_`。
4. 总评正文 = report.md 的「这次改动在做什么」+「需要人工判断」+「覆盖缺口」+「校准数据」四段，同样附 footer。`submit_pending` 时 event 用 COMMENT，不用 REQUEST_CHANGES 或 APPROVE，approve 是人的事。
5. 输出发布了几条行内评论、总评链接。

发布前把行内评论列表先展示给用户确认一次；用户已明确说过直接发的除外。
