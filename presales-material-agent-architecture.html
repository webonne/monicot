分层架构

自上而下五层，运营与治理纵向贯穿

上层只依赖下层的对外能力：工作台不直接读知识库，Agent 不自己实现检索与渲染。每层可独立替换——换模型不动交互，换知识源不动 Skill。

用户与接入 / 运营治理 交互与 Agent 编排 能力服务与知识资产 深蓝实心块 = Agent 的六个执行阶段

主流程

三条泳道、七个步骤，三条回流路径

实线为主链路，虚线为回流：信息不足时的澄清、大纲不认可时的调整、成稿不满意时的局部重写。只有"确认大纲"是强制人工卡点。

步骤主责做什么产出与把关点
① 提出需求用户选场景与产品线，描述客户情况：受众、痛点、关注能力、输出语言与篇幅、交付时间。一份结构化需求。必填项缺失时不允许提交，减少后续澄清轮次。
② 需求理解与澄清Agent拆解意图与约束，识别信息缺口；缺口成立时一次性列出待补信息，而不是逐条追问。澄清问题不超过一轮；用户补充后继续，跳过也能按默认假设往下走并在稿中标注。
③ 检索与选材知识 + Agent按用户可见范围做混合检索，排序去重，标注资料时效与版本。候选素材清单（含来源）。权限过滤在检索侧完成，越权资料不进入候选。
④ 拟定并确认大纲Agent → 用户Agent 给出叙事结构与价值主线，每节标明将引用的素材；用户确认或调整。大纲是唯一需要人工确认的强制卡点——改大纲远比改成稿便宜。
⑤ 分节生成初稿Agent按节生成，遵循模板与版式规则，引用标准技术原图而非重画。分节生成使局部重写成为可能，不必整篇重来。
⑥ 自检与合规校验事实与引用核对、引用完整性、对外口径红线与敏感信息扫描。不通过的小节回流到 ⑤ 重写；无法自动判定的标黄，提示人工确认。
⑦ 预览、交付与沉淀用户在线预览编辑、局部重写、在线演示或导出 PPT / Word / PDF，给出赞踩与意见。成稿入库并采集埋点：澄清轮次、编辑量、采纳与否，回流到运营闭环。

澄清、调整大纲、局部重写三条回流都不重置已确认的内容：补充信息只重跑检索与大纲，调整大纲只重跑受影响小节，局部重写只重写选中段落。

关键能力与服务

能力层的每一项都对应一个真实会出问题的地方

能力解决什么问题设计要点
混合检索 + 权限过滤召回不全、或渠道用户看到内部资料向量与关键词混合召回后重排；ACL 下推到检索层（不是"先查全再过滤"），按产品线、场景、行业、语言、版本过滤；过期知识降权并标注。
引用与溯源服务材料写得像那么回事，但没人敢用按 chunk 级保留来源，成稿附引用页，预览时可回跳原文；没有来源支撑的句子标黄，不静默生成。
Skill 与模板体系每个人产出的材料风格、口径都不一样生成规则、提示词、版式模板三者分离维护，按场景与产品线选用；运营侧可热更新，不需要发版。
标准图件与素材服务架构图手绘、版本对不上技术原图与演示素材按产品线、版本登记，生成时按标签引用；原图更新后可批量提示受影响材料。
自检与合规对外材料出现错误承诺或敏感信息生成后、交付前的强制关卡：事实一致性、引用完整性、对外口径红线、客户与项目敏感信息扫描。
渲染与导出还要人工再排一遍版统一渲染为 PPT / Word / PDF，保留品牌版式；导出可带水印与有效期，渠道侧默认开启。
材料库与复用相似需求反复从零生成成稿入库、可检索可复制；新需求先匹配历史材料，命中则改写而非重写，同时沉淀优质样例。
观测与埋点上线后说不清好不好用全链路埋点：澄清轮次、检索命中率、生成时长、编辑量、导出率、采纳与赞踩，支撑归因与回归评测。

运营与治理闭环

指标 → 归因 → 改知识或改 Skill → 评测 → 发布

看得见

指标监测

使用量、澄清轮次、检索命中率、成稿时长、人工编辑量、导出率、采纳与赞踩。按场景与产品线分组，异常自动告警。

找得到原因

评价归因

把一次差评拆到具体环节：是知识缺失、检索没召回、Skill 规则不对，还是模板版式问题。归因结论直接落到知识运营或 Skill 运营的待办。

改了有验证

样例集回归评测

维护典型需求样例集，知识或 Skill 变更前后跑一轮评测，比对通过率与引用准确率，通过后再发布，避免改好一个场景、改坏三个。

运营入口分两类：知识运营（新增 / 更新 / 下架、时效巡检）与 Skill 运营（生成规则、提示词、模板、口径红线）。两者都需要版本与灰度，变更记录可回溯。

整体结构知识库 / Agent / 用户界面 三块并列，① 至 ⑦ 在框与框之间来回跳。拆成"五层架构 + 一条主流程泳道"两张图。看架构的人先看清依赖关系，看流程的人再看时序，一张图不承担两件事。
权限Agent 内部"按权限选取知识"。权限下推到检索服务，知识层带访问标记，登录态携带可见范围。判断点只有一处。渠道用户接入后不会拿到内部资料，这是能不能对外放的前提。
质量把关生成初稿后直接进入用户预览。新增"自检与合规"节点：事实、引用、口径红线、敏感信息。售前材料要发给客户，错口径的代价远高于多等十几秒。
溯源"保留资料来源"写在检索步骤的说明里。提升为独立服务：chunk 级来源、成稿引用页、可回跳原文。用户需要能自证材料可信，否则仍要自己再查一遍。
迭代路径只有"在线预览与编辑调整"一条回流。明确三条回流：澄清补充、调整大纲、局部重写。不满意时不必整篇重生成，时间与成本都可控。
成果沉淀导出下载即流程终点。成稿入库 + 埋点，进入材料库与运营闭环。复用率与采纳率是这类 Agent 的长期价值，不能只看单次生成。
运营位置运营作为底部第四个并列模块。作为贯穿全层的纵向能力，形成 指标 → 归因 → 评测 → 发布 闭环。运营既要改知识与 Skill，也要能看到改完之后的效果。

原图中的"知识内容与标准素材""知识分类与标签""Skill 生成规则与执行步骤""认证登录""评价与反馈"等要素全部保留，只是被放到了更合适的层次上。

分期落地建议

先跑通再可信，最后才对外放

阶段范围完成标志
一期｜跑通主链路需求表单、澄清、检索选材、大纲确认、分节生成、在线预览、导出。权限过滤与引用溯源必须在一期，不作为增强项后置。内部售前能端到端产出一份可用初稿，且每段内容都能查到出处。
二期｜可信与好用自检与合规、标准图件服务、局部重写、模板与版式规范、材料库与复用。一次通过率与人工编辑量达到约定阈值，材料库开始产生复用。
三期｜对外与闭环渠道用户接入与可见范围、导出水印、指标看板、样例集回归评测、Skill 热更新。渠道可自助使用；运营能按周迭代知识与 Skill，并用评测验证改动。

分期顺序的依据：没有权限与溯源，材料不敢用；没有自检与合规，不敢对外；没有指标与评测，运营改不动。

边界与待确认

避免把设计稿当成已定方案

注意

本页范围：只描述应用架构与主流程，不含部署形态、容量评估、网络与集成方案，也未包含模型选型的性能与成本测算。图中各层能力为设计意图，具体实现方式待技术方案评审。

待确认事项：① 渠道用户可见的知识范围与导出水印策略；② 对外口径红线由谁维护、谁审核；③ 导出格式优先级（PPT 是否优先于 Word）；④ 是否允许用户上传客户文档作为一次性上下文——涉及数据留存与隔离；⑤ 模型选型及是否需要私有化部署；⑥ 一次通过率与编辑量的具体验收阈值。
